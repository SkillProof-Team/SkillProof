## 本轮实现与实际契约

- 岗位选择继续使用真实 catalog 的 `enabled`，选岗位时保留会话复查。
- “开始 / 继续测评”事件先获取当前会话和 CSRF，再 `POST /api/attempts`，成功后进入 `/attempts/{id}`。创建不在组件 Effect 中执行，使用同步请求锁防双击。
- 测评组件只通过 ID 读取；刷新先恢复登录状态，再读取同一 ID 的状态和服务端草稿。选项、题量和进度来自接口，前端没有固定为 18 题。
- `PUT /api/attempts/{id}/answers` 发送完整当前答案，空数组清除。保存失败保留本地答案及未保存标记；成功响应必须确认本次答案。
- 未答完时定位第一道未答题；提交先等待保存，再 `POST /api/attempts/{id}/submit`。失败后查询状态确认是否已经提交；保存遇到 409 时也查询已提交状态，避免继续修改旧答卷。
- 未保存或写请求进行中时阻止站内导航及同文档前进/后退，并提示原因；刷新/关闭使用 `beforeunload` 提醒。不会将答案或认证凭据写入 localStorage。恢复范围是服务器已保存答案，实际会话失效时会清除本地未保存修改。
- 请求有 30 秒超时及组件卸载取消。401 使用 #19 的会话清理；403、404、409、422、网络和服务端错误沿用真实接口错误提示。
- 提交后以 replace 导航到 `/reports/{id}`，避免后退又自动进入结果页的循环。#25 此路径仅有入口提示，不实现评分展示。#23 后续在该分支挂载原有 `ResultPage`，参数仍是同一测评 ID。

核对的后端实现为 #28 的 `api_assessments.py` / `assessment_dependencies.py`、#27 的 `scoring.py` / `reports.py` 和 #30 的认证、会话及 catalog：

| 接口 / 行为 | 当前实现 |
| --- | --- |
| 同岗位创建 | 返回已有进行中记录；不同开放岗位与当前测评冲突返回 409 |
| 所有权 | 不存在或其他用户的测评、报告均返回 404 |
| 保存 | 合并答案；未传保留、空数组清除；提交后返回 409 |
| 提交 | 必须全部作答；事务保存状态、时间、评分版本和报告；重复提交返回原结果 |
| 报告 | `/api/reports/{id}` 返回已保存快照；未提交返回 409 |
| 评分 | 综合分按难度 1/2/5 归一化，六维按答对题数比例；前端不重复计算 |
| 抽题 | #28 暂用每维 2 easy + 1 medium；与共享文档的三难度蓝图仍需团队确认 |
