## 开始前要确认的事项

1. **题库发布状态。** 当前 42 道题均为 `draft`。人工复核记录填写了“通过”，但文中仍有未复核说明，`manifest.json` 也仍为 `pending_human_review`。内容负责人需核对实际复核结果、来源和发布状态；QA 不直接把草稿改为已发布来代替正式验收。
2. **抽题规则。** 已合并的测评约定为每维两道简单、一道中等，共 18 题，只从已发布题目中抽取；验收时核对六维题量、难度、不重复及题库不足的处理。纯评分中的困难题样例用于验证评分函数对历史快照的支持，不代表当前新建测评会抽困难题。
3. **受测版本。** 待合并 PR 先同步最新 main，处理冲突，并登记本次必测项。每次执行记录 PR 和完整提交版本；修复或集成改变相关代码后，复测受影响项目。临时组合分支的结果不记成最终 main 验收结果。

题库发布前，可先测认证、数据库、评分及使用隔离测试数据的接口流程，并注明数据来源；正式题库流程仍保留为待验收项。

## 准备与顺序

按 README 启动项目，使用独立测试数据库和两个测试账号。先测能单独运行的数据库和评分，再测接口，最后操作完整页面。功能未接好的部分先记为“阻塞”。

## 测试步骤

**01 启动项目**

安装依赖，运行前端 lint/build，启动前后端并访问健康接口。重复初始化数据库，检查已有数据没有被覆盖；检查题库数量和格式与说明一致。

**02 注册和登录**

账户接口接好后，注册新账号，退出后重新登录，再刷新页面。应能恢复正确身份，退出或会话过期后不能访问私有数据。另试重复注册、错误密码、空值及姓名和密码长度边界，应有错误提示，响应不包含密码或哈希。

**03 选择岗位、创建测评**

登录且题库可用后，选择开放岗位，创建测评，再重复点击创建。应恢复同一份进行中测评，题量、六维和难度符合确认的规则，响应不含正确答案和解析。未开放岗位或题库不足时应拒绝创建，不留下不完整记录。

**04 答题和保存**

进入测评，分别做单选、多选，切题、保存、清空一题，再刷新并重新进入。已保存答案应能恢复，进度正确。另通过接口提交非法题号、选项和错误数据类型，应被拒绝，原草稿不变。

**05 提交测评**

先在未答完时提交，应提示无法提交且保留草稿。全部答完并保存后再提交，应保存状态、时间和结果。重复及并发提交只评分一次，提交后不能改答案；模拟评分失败时草稿仍保留。之后再次测评，应生成新记录且保留旧结果。

**06 核对评分和结果**

评分接好后，用已知答案检查全对、全错、多选漏选和选错；多选须全部选对才得分，选项顺序不影响结果。按确认的规则手算综合分、六维分数、精度及薄弱项排序。另用“30 题、某维 5 题全对”的样例检查该维为 100 分。网页、接口和数据库应一致，修改当前题库不应改变原题卷或已存报告。

**07 检查权限和异常**

准备账号 A、B，用 B 获取、修改、提交 A 的测评或查询 A 的报告，应被拒绝。未登录、缺少或使用其他会话的 CSRF、查询不存在或未提交的报告也应按接口约定处理。页面测试保存失败、提交响应丢失、重复点击和重试，应有提示且不重复生成结果。

**08 完整操作和重启**

页面接好后，在浏览器完成注册→登录→选岗位→答题→保存刷新→提交→结果，检查报告页能直接打开和刷新，桌面与手机宽度下显示正常。正常关闭服务后保留数据库，再启动并登录，草稿和报告应仍在。

## 自动化和记录

自动化至少覆盖三条真实接口流程：注册登录、保存答案后提交、查询并核对六维结果。复用已有测试，记录实际运行命令和输出。

开发者随功能分支维护对应测试与必测登记；QA 核对业务覆盖范围、补充遗漏场景，并负责最终整合验收。业务流程用例放在 `tests/acceptance/test_*.py`；已经合入 main 的功能，其补充测试随本测试任务交付。每个 PR 的必测清单只登记本次相关用例，CI 仍运行全部已有验收测试。

页面真实操作单独记录。现有 CI 的前端检查是代码检查和构建，没有浏览器点击测试；前端 PR 的自动化必测项应验证本次前端改动，不用无关的后端旧用例代替。浏览器验收与自动化结果分别统计。

执行时在 01—08 下细分用例，每条记下日期、执行人、代码版本、环境、前置条件、操作步骤、预期和实际结果，标为“通过／失败／阻塞／未执行”，附必要截图或日志。发现问题另建 Bug Issue，修复后按原步骤复测。没有执行结果的项目不计为通过。

报告材料随测试保存：场景步骤用于场景测试说明；逐项结果用于测试结果表；Bug 与复测记录用于问题清单；最终演示版本的完整流程、数据持久化和剩余问题用于交付结论。

最后在 `alpha-test-report.md` 汇总通过、失败、阻塞和未执行数量，说明剩余问题，并对最终演示版本再测一遍，经另一名成员 Review 后交付。
