# 后端题库数据与接入约定 v0.1

关联 Issue #5、#41。当前题库版本为 `0.1.3`，依据 `0.1.2-draft` 的独立复核记录补齐参考来源后，42 道题均已发布。难度为产品标注，未经学生样本实测校准。题库位于服务端 `backend/app/content/`，不进入前端源码或静态资源。

## 1. 本轮范围

本轮提供 42 道 AI 原创中文后端选择题，以及能力树、独立复核记录和格式说明。暂停外部题库接入，不依赖 Open Interview 数据。题目格式和公开字段遵循当前项目的 API 契约，内容状态由本项目独立维护。

当前 [API 契约](api.md) 仍是 HTTP 调用约定的依据，本文件不新增路由，不修改响应、认证或业务行为。测评创建、答案保存、提交及结果查询由现有后端接口提供。

## 2. 文件与服务端边界

| 文件 | 内容 |
|---|---|
| [questions.json](../../backend/app/content/questions.json) | 42 个完整题目记录组成的数组，包含正确答案和解析，仅服务端使用 |
| [ability-tree.json](../../backend/app/content/ability-tree.json) | 后端岗位、六维说明与稳定知识点标识 |
| [manifest.json](../../backend/app/content/manifest.json) | 数据版本、原创说明、审核状态与文件 SHA-256 |
| [ability-tree.md](ability-tree.md) | 能力定义、知识点与题量统计 |
| [question-bank-review.md](../testing/question-bank-review.md) | 独立审核信息、原始提交及发布补充记录 |

题库文件不能通过静态文件挂载、前端 import 或原样响应暴露。本次修复只更新默认题库、文档与回归测试，不新增 HTTP 接口。

## 3. 完整题目格式（仅服务端/内容维护使用）

`questions.json` 顶层为数组。每题包含以下字段：

| 字段 | 类型及约束 |
|---|---|
| `id` | 稳定、非空、全库唯一字符串；本批格式 `SP5-PRG-001` 等，保持全库唯一且稳定 |
| `dimension` | `programming / algorithms / database / network / os / software` 之一 |
| `topicId` | 本地能力树内的稳定知识点 ID，例如 `programming.queue`；必须归属于该题维度 |
| `topic` | 知识点显示名，与 `topicId` 在能力树中的名称一致 |
| `type` | `single` 或 `multiple` |
| `difficulty` | `easy / medium / hard`；为初始产品标注，未经实测校准 |
| `stem` | 完整中文题干；涉及代码、并发、成本模型等，须给出必要前提 |
| `options` | 本批恰好 4 项，每项只含非空字符串 `id` 和 `text`；ID 为 A/B/C/D，文本不可重复 |
| `correct` | 不重复的选项 ID 数组；单选恰好 1 项，多选至少 2 项且少于全部选项 |
| `explanation` | 解释答案及干扰项为何不满足题设；不能只写选项字母 |
| `sources` | `[{"title": "资料标题", "url": "https://…"}]`；已发布题目至少一条；参考资料支持知识点，不表示题目从该资料复制 |
| `version` | 正整数，从 1 开始；正式使用后的实质变更须增加版本 |
| `status` | `draft / published / archived`；本批 42 道均为 `published` |

`correct` 为正确选项 ID 数组，题型和难度值按本文约定；`topicId` 为内部知识点关联字段，不属于现有公开测评协议。`topic` 保留显示用途，改名不能通过更换 ID 破坏历史引用。

本批原创来源统一记录于 `manifest.json` 的 `origin: ai_original` 和 `contentNote`。审核记录来自王斯语在 2026-11-01 的提交 `364def2fddad8d701a14114e965b06bcfda2b40a`，范围为全部 42 题。manifest 保留被审核版本、记录路径和提交号；补充参考资料与发布状态不改变已审核的题干、选项、答案、解析和难度。

## 4. 对现有 HTTP API 的投影

现有创建/获取测评接口中的每题仍只使用以下公开白名单：

```json
{
  "id": "SP5-PRG-001",
  "dimension": "programming",
  "type": "single",
  "stem": "一个后台任务容器要求最先加入的任务最先被取出。不考虑任务优先级，应采用哪种基本数据结构？",
  "options": [
    {"id": "A", "text": "栈：只从栈顶加入和移除"},
    {"id": "B", "text": "队列：从队尾加入、从队首取出"},
    {"id": "C", "text": "集合：只保证元素不重复"},
    {"id": "D", "text": "无序映射：按键查找任务"}
  ]
}
```

生成响应时逐层构造白名单：顶层只取 `id, dimension, type, stem, options`，每个选项只取 `id, text`。不能把完整题目直接返回，也不能只删除一个 `correct` 字段后返回剩余内容。

以下字段不进入进行中测评：`correct`、`explanation`、`sources`、`topicId`、题库审核信息，以及将来添加的任何内部元数据；本轮也不擅自把 `difficulty / topic / version / status` 加入现有最小响应。新增公开字段须由相关负责人协商并同步更新 API 契约。

用户作答沿用现有接口：

```json
{"answers": {"SP5-PRG-001": ["B"]}}
```

这里是用户自己的选择，不是服务端回传的正确答案。服务端必须检查题目属于本次测评、选项存在、单选最多一项；空数组仍表示清除该题答案。不允许提交分数、正确答案或客户端指定题库版本来改变评分依据。

当前报告 API 只约定维度得分，本轮不新增题目讲解或 review 响应。若下一阶段需要已提交后的逐题解析，应先补充明确协议、所属用户检查和状态限制。

## 5. 题量、抽题与评分衔接

- 每维 7 题：easy 5、medium 2、hard 0；每维单选 4、多选 3。
- 总计 42 题：easy 30、medium 12、hard 0；单选 24、多选 18。
- 当前采用 `alpha-18-easy12-medium6-v1`。每次测评共 18 题，每维 2 道 easy、1 道 medium，合计 easy 12、medium 6、hard 0。当前已发布题库的数量分布满足该配额，可直接创建测评。
- T06 仅抽取 `published` 题目。每维已发布 easy 不足 2 道或 medium 不足 1 道时返回 503，不以其他难度、`draft` 或 `archived` 题目补足。
- 已有测评继续使用原题目快照，历史报告读取已保存的结果。manifest 的难度说明已同步当前蓝图。
- 评分沿用精确集合相等规则：用户选项集合与 `correct` 集合完全相同才答对；漏选、多选、错选不得给部分分。重复 ID 等非法输入应先拒绝，不能通过转集合掩盖。
- 本文件不新增权重或岗位胜任结论。难度、题量、维度划分均是产品设定。

## 6. 加载、校验与版本

1. 后端启动时校验 `QuestionInput`、manifest 题数和文件 SHA-256；已发布配额由回归测试及抽题接口检查。同步规则见 [题库同步与本地重置](../testing/question-bank-sync.md)。
2. 检查唯一 ID、六维、知识点引用、选项、正确答案、完整文本和难度覆盖；不修复或猜测缺失答案。
3. 正式发布前要求真实人工审核通过，补齐已实际核对的资料来源，并满足发布规则；草稿结构校验通过不能把状态自动改成 published。
4. 对已用于测评的题目做实质修改时增加题目 `version`，题库更新同步修改 bankVersion 和文件散列。全新题使用新 ID；删除或替换不得复用旧 ID 表示不同内容。
5. 创建测评时保存题目、选项、答案和相关版本的不可变快照；不得用后来修改的题库重新计算历史报告。快照持久化由测评实现负责，本文没有新增数据库表。

本版 42 题已依据独立复核记录补齐来源并发布。后续发布仍须检查审核范围、资料与发布状态，不能因结构校验通过就自动发布；当前没有后台发布 API。启动时按题库版本和题目版本事务同步，旧草稿库会升级到当前已发布题目；本地编辑冲突会阻止覆盖。旧测评继续使用既有快照，见 [Issue #41 验证与部署说明](../testing/issue-41-default-question-bank.md)。

## 7. 下一阶段接入外部题库

未来以适配器离线转换到相同完整记录格式，不让前端依赖具体来源。外部条目还应保存独立的来源映射：内部题目 ID、上游 ID、固定提交/版本、文件及记录位置、原始类型/难度、许可证与版权通知、编辑说明及审核记录。

建议流程为：下载至过程目录 → 核查许可 → 结构识别 → 原文与语义去重 → 六维/知识点映射 → 答案与解析审核 → 输出 draft → 人工复核 → 独立验证 → 审核后发布。问答题不能因有 answer 字段就自动当成选择题；缺失答案不得推断。第三方原始数据、下载仓库和转换日志保存在独立研究目录，不直接纳入项目。

来源改变不应影响 `GET /api/catalog`、测评题目公开形状或用户作答格式。未来若需新增字段或改变行为，由相关负责人同步修订当前 API 文档；本轮不新增网络下载器或面向公网的导入接口。

## 8. 回归校验要求

维护题库时应检查唯一题目 ID、六维名称与 API 一致、知识点引用有效、选项和答案合法、各维配额满足蓝图、manifest 文件 SHA-256 与实际内容匹配，并保持公开字段投影不泄漏正确答案和内部元数据。

当前版本为 30 道 easy、12 道 medium，全部 published；题干、选项、答案、解析与难度沿用已审核草稿，补充 sources 并逐题增加 version。

后续加载实现至少应检查第 3、5、6 节的约束，并对题库缺失分层、非法答案、重复 ID、未审核发布和内部字段泄漏增加回归测试。
