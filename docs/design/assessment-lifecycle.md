# T06 测评生命周期

关联 Issue #8。实现创建、获取、草稿保存和提交。评分由 T07 的 `build_report(attempt, submitted_at)` 提供。接口路径、响应字段和已确认的抽题比例见 [API 契约](api.md)，数据结构遵循 [数据库设计](database.md)。

## 接口和状态

| 接口 | 行为 |
| --- | --- |
| `POST /api/attempts` | 接收 `roleId`；开放岗位创建新测评，相同岗位已有进行中记录则恢复该记录 |
| `GET /api/attempts/{id}` | 获取所属测评的状态、公开题目和用户已保存选择 |
| `PUT /api/attempts/{id}/answers` | 携带 `expectedVersion`，事务内校验并递增 `answersVersion`；合并答案，未传题目保留，空数组清除；版本冲突或已提交返回 409 |
| `POST /api/attempts/{id}/submit` | 全部作答后评分，原子保存状态、时间、评分模型版本与结果；重试返回原结果 |

测评 ID 为 UUID。当前沿用每用户全局最多一个进行中测评；切换到其他开放岗位返回 409。已提交记录保留，之后可以创建新测评。

创建、保存和提交均使用数据库公共 `transaction()`（`BEGIN IMMEDIATE`），串行化读取及写入决策。并发创建恢复同一记录，并发提交只对首次提交评分。评分或写入异常回滚本次提交，之前保存的答案保留。

PR #25 修复超时后的乱序保存：创建、获取和保存均返回 `answersVersion`，新旧记录初值为 0。保存请求必须提供严格非负整数 `expectedVersion`；在写锁内读取后比较，不一致返回 `answers_version_conflict`，不改答案。成功保存与版本加一在同一事务中提交。两个旧版本请求无论到达顺序如何最多一个成功，后到者同步版本后方可重试。前端同步时保留未保存选择；响应丢失且查询版本尚未前进时仍显示未确认，防止仍在途中的请求改变服务端状态后页面误报已保存。

## 题卷与快照

当前蓝图为 `alpha-18-easy12-medium6-v1`：六个维度各三题，每维2道 easy、1道 medium，共18题（easy 12、medium 6、hard 0）。配额统一读取 `catalog.BLUEPRINT`，同一次测评不重复抽题。仅选择状态一致、通过服务端模型校验的 `published` 题目；每维已发布 easy 不足2道或 medium 不足1道时返回 503，不创建半成品测评，不自动使用草稿或替换难度。

### 2026-11-01 蓝图调整记录

问题：首批42题每维5道 easy、2道 medium、0道 hard，无法满足原每维三难度各一题方案。

2026-11-08，hope3243 记录本轮确认结果。Alpha 采用 `alpha-18-easy12-medium6-v1`，每维 2 道 easy、1 道 medium，共 18 题。这个比例保留总题量和六维覆盖，也符合首批题库的难度分布。API、能力树和题库约定已同步，草稿题按原发布流程处理。

适用范围：仅新建测评使用新蓝图版本。已有进行中测评恢复原题卷，已有报告保留原结果；仍支持旧快照中的 hard 交由评分函数正常处理。后续补充 hard 或再次调整比例时，需使用新版本，并同步文档和回归测试。

同一用户的历史测评快照用于识别已见题。每个分层优先选择未见题，分层题目均已见时允许复用，并记录复用数量。历史已见题从现有 `attempts.questions_json` 计算，无须额外题目使用记录表。

创建时完整保存题目及岗位配置快照，`resources_json` 显式写入 `[]`。之后恢复、保存和评分使用题卷快照；不重新读取当前题库计算旧测评。学习任务、资源推荐不在本任务内。

公开题目逐层使用白名单：`id / dimension / type / stem / options`；选项仅 `id / text`。正确答案、解析、来源、知识点、难度、题库状态及后续内部字段均不随测评响应返回。

## 身份和输入

测评复用 T04 的 `security.require_user` 和 `security.get_db`，与报告查询使用相同的会话和数据库配置。

- 身份从服务端 `sessions` 表校验，验证会话有效期；写请求校验会话绑定的 CSRF Token 和请求来源。客户端不能指定归属用户。
- 查询测评同时约束 `id` 和 `user_id`；不存在与非本人记录均返回 404。
- 复用数据层 `AttemptInput / AnswersInput`，拒绝未知字段、重复选项、无效选项、错误的数组格式；同时按快照验证题目归属和单选数量。
- 测评创建使用 T04 岗位接口的 `enabled` 状态。

## 评分接入

提交向 T07 传入服务端保存的 `id / role / createdAt / questions / answers` 及本次提交时间。题目包含 T07 所需的 `difficulty / correct / options`。评分计算不在 T06 内重复实现。

评分调用 T07 的 `build_report`。未答完或评分抛出 `ScoringError` 时返回 422，提交事务回滚，已保存的答案保留。状态、时间、评分版本和报告在同一事务中保存。

报告查询由 T07 的 `GET /api/reports/{id}` 提供。重复提交读取同一份已存报告。

正式题库发布和浏览器联调另行验证。后端验证见 [测评验证记录](../testing/assessment-lifecycle.md)。
